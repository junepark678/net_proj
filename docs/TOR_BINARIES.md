# Tor binary sources

Part of #5: this is prerequisite binary discovery only. The chosen desktop bundle location is `build/tor/` and the download script is `tools/fetch_tor.sh`. The future Kotlin `TorProcess` actual will first locate `build/tor/<platform>/tor/tor` (`tor.exe` on Windows), then fall back to `tor` on `PATH`. Remaining #5 work: expect/actual implementation, torrc generation, port discovery, stop/restart, and the JVM bootstrap test. These remain open in issue #5.

For authenticity, verify `.asc` using GPG and the Tor Browser Developers signing key obtained through Tor Project's official key distribution; SHA-256 detects corruption and is pinned above. The script verifies SHA-256 before extracting. Run `tools/fetch_tor.sh` on a supported host.

The Android coordinates and packaging were verified with `curl` against `repo1.maven.org`; the AAR contains all four ABIs listed above. The [matching tag README](https://github.com/guardianproject/tor-android/blob/tor-android-binary-tor-0.4.7.14/README.md) supports using `libtor.so` directly as a daemon (its dependency example still shows an older version). The pinned [Tor source configure.ac at 86771da](https://github.com/guardianproject/tor/blob/86771da/configure.ac) declares 0.4.7.14.

The script preserves `tor/`, `data/` (including `geoip` and `geoip6`), and `docs/` (licenses) under `build/tor/<platform>/`. A successful install writes `.completed-sha256` containing the expected archive digest; reruns compare it directly and reuse the installation offline. On Linux, set the child process's `LD_LIBRARY_PATH` to the installed `build/tor/<platform>/tor/` directory so bundled libevent/libssl libraries resolve.

## Tor configuration notes

Use `SocksPort auto`, `ControlPort auto`, `CookieAuthentication 1`, `ControlPortWriteToFile <private-path>`, `DataDirectory <private-path>`, `Log notice stdout`, and `ClientOnionAuthDir <private-path>`. Keep data and onion authorization files private. `ControlPortWriteToFile` writes `PORT=<address>:<port>`, for example `PORT=127.0.0.1:9051`; see [Tor src/feature/control/control.c](https://github.com/guardianproject/tor/blob/86771da/src/feature/control/control.c). It never writes a `COOKIE=` entry. Read the 32-byte binary authentication cookie from `<DataDirectory>/control_auth_cookie` (or the configured `CookieAuthFile`), separately from the port file. Parse the address and port without assuming a fixed port.

Android needs a foreground service while Tor remains available: declare a service type appropriate to the active work (`microphone` for an active call and `dataSync` only where policy/OS rules permit), and required foreground service permissions. Long-lived services are affected by Doze and vendor battery restrictions; explain the persistent notification and allow users to go offline. `android:process` changes app/service process ownership and lifecycle; keep Tor and its control client in a deliberately coordinated process. `extractNativeLibs` controls whether packaged native libraries are extracted; if false, do not assume a filesystem path exists. The direct daemon consumer must enable extraction (`extractNativeLibs=true`) and use the native library path described above.
